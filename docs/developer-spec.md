# 第1部 全体像

## 1. システム概要

お客様がLINEから予約を申し込み、スタッフが内容を確認して確定する、**仮予約 → スタッフ承認 → 確定** の2段階方式の予約システムです。

| 誰が | 何をするか | 使う画面 |
|---|---|---|
| お客様 | LINEのリッチメニューから予約フォームを開き、日時・人数・スペースなどを入力して申し込む | LIFF予約フォーム（GitHub Pages） |
| スタッフ | Discordに届いた通知のリンクを開き、内容を確認・修正して承認する | 承認画面（GAS） |
| スタッフ | 予約の一覧・検索、却下・キャンセル、人数変更、電話予約などの代理登録、ユーザー管理 | 管理者画面（GAS） |
| システム | 確定時にGoogleカレンダーへ登録、お客様にLINE/メールで通知、前日にリマインド | GASの処理・トリガー |

### 設計方針

- **すべて無料枠**: GitHub Pages / Google Apps Script / Googleスプレッドシート / Googleカレンダー / Discord Webhook / LINE Messaging API / MailApp。サーバーやデータベースを別に用意しない
- **最終判断は人**: 空き状況は粗い目安にとどめ、受けるかどうかはスタッフが承認画面で決める。スペースや時間帯ごとの在庫管理はしない
- **スプレッドシートが唯一の正**: 予約の状態はシートだけで決まる。カレンダーは確定予約の「写し」で、空き状況の判定には使わない
- **失敗しても止めない**: 通知やカレンダー登録が失敗しても予約処理そのものは完了させ、Discordで警告してスタッフが手で補う
- **ビルドなし・依存なし**: フロントは素のHTML/CSS/JS、GASは標準サービスのみ（ライブラリなし）

└──────────────────────┘                      │       │       │

        │ 承認リンク            Googleスプレッドシート  Googleカレンダー  外部通知
┌───────┴──────┐               （予約台帳＝DB）       （確定予約の記録   ├ Discord Webhook（スタッフ向け）

| レイヤー | 技術 | 補足 |
|---|---|---|
| フロントエンド | 素のHTML/CSS/JS（ビルドなし）＋ LIFF SDK v2（`https://static.line-scdn.net/liff/edge/2/sdk.js`） | GitHub Pagesで公開。LIFFはHTTPS必須 |
| バックエンド | Google Apps Script（V8ランタイム） | Webアプリとして1つのURLで公開（`doGet`/`doPost`） |
| DB | Googleスプレッドシート | シート「予約一覧」が台帳、古いデータは「予約一覧_archive」 |
| カレンダー | Google Calendar（`CalendarApp`） | 確定予約の記録先。日本の祝日の取得にも使う |
| 通知 | Discord（またはSlack）Webhook / LINE Messaging API / MailApp | |
| デプロイ | clasp（GAS） / GitHub Pages（フロント） | |

GASプロジェクトの設定（`gas/appsscript.json`）:

```json
{
  "timeZone": "Asia/Tokyo",
  "exceptionLogging": "STACKDRIVER",
  "webapp": { "executeAs": "USER_DEPLOYING", "access": "ANYONE_ANONYMOUS" },
  "runtimeVersion": "V8"
}
```

| 設定 | 意味 | この設定にしている理由 |
|---|---|---|
| `timeZone: Asia/Tokyo` | `new Date()` の解釈や `Utilities.formatDate` の基準 | 日付判定をすべて日本時間で行うため |
| `exceptionLogging: STACKDRIVER` | 例外をCloud Loggingに残す | GASエディタの「実行数」画面でエラーを追えるようにするため |
| `executeAs: USER_DEPLOYING` | 誰が開いてもスクリプト所有者の権限で動く | 訪問者にスプレッドシート等の権限を配らずに済むため |
| `access: ANYONE_ANONYMOUS` | Googleにログインしていない人も開ける | LIFFからの `fetch`（Cookieなし）と社外スタッフのアクセスに必要 |

この組み合わせのため、**画面を開いた人なら誰でも所有者の権限でサーバー関数を呼べる**状態になっています。対策は[17章](#17-セキュリティ設計)。

## 3. 業務フローと予約ステータス

### 3.1 ステータス

予約のステータスは3つです（シートの「ステータス」列の文字列。コード中でも日本語の文字列のまま比較しています）。

```
            お客様が申し込む / 管理画面で「仮予約」として追加
                         │
                         ▼
                    ┌─────────┐   却下（管理画面）
                    │ 仮予約   │ ───────────────────┐
                    └────┬────┘                     │
       承認（承認画面 /   │                          ▼
       管理画面）        ▼                     ┌──────────┐
                    ┌─────────┐  キャンセル     │ キャンセル │
 管理画面で「確定」 ─▶│  確定    │ ────────────▶ └──────────┘
 として追加          └─────────┘  （管理画面）
                                                    │
```

「却下」と「キャンセル」は、どちらもサーバー側では同じ `cancelReservation()` で、ステータスは「キャンセル」になります。元が仮予約か確定かで、通知の文面とカレンダー削除の有無が変わります。シート上で「却下」と「キャンセル」は区別できません。

### 3.2 各操作で起きること

| 操作 | 関数 | シート | カレンダー | Discord | LINE（UserIdあり） | メール（アドレスあり） |
|---|---|---|---|---|---|---|
| お客様が申し込む | `doPost` | 行を追加（仮予約） | — | 新規予約通知＋承認リンク | 仮予約受付 | 仮予約受付 |
| 承認する | `approveReservation` | 確定に更新（編集内容も反映） | 予定を作成し、IDを保存 | 確定報告 | 確定通知 | 確定通知 |
| 却下する（元が仮予約） | `cancelReservation` | キャンセルに更新 | — | 却下報告 | お断り | — |
| キャンセルする（元が確定） | `cancelReservation` | キャンセルに更新 | 予定を削除 | キャンセル報告 | キャンセル通知 | — |
| 人数を変更する | `updateReservationHeadcount` | 人数を更新 | 確定済みなら予定タイトルを更新 | 「○名 → ○名」 | — | — |
| 管理画面から追加（確定） | `createReservationByAdmin` | 行を追加 → 承認処理 | 予定を作成 | 確定報告 | —（UserIdなし） | 確定通知 |
| 管理画面から追加（仮予約） | `createReservationByAdmin` | 行を追加（仮予約） | — | 【管理画面から追加】＋承認リンク | — | —（※） |
| 前日リマインド | `sendReminders`（毎朝9時台） | — | — | リマインド | リマインド | リマインド |
| 古いデータの退避 | `archiveOldReservations`（毎月1日） | archiveシートへ移動 | — | — | — | — |

※ 仮予約受付メールの文面が「担当者よりLINEにてご連絡いたします」なので、LINE連携のない代理登録では送りません。

**二重実行の防止**: 承認済みの予約をもう一度承認したり、キャンセル済みの予約をもう一度キャンセルしたりした場合（連打・再読み込み・リンクの二重クリックなど）は、何もせずに成功を返します。カレンダーの二重登録や通知の二重送信は起きません。

**部分的な失敗の扱い**: カレンダー登録・削除、LINE送信、メール送信のどれかが失敗しても**予約処理そのものは続行**し、Discordに「⚠️ 〜に失敗しました（予約ID …）」と警告を出します。スタッフが手動で対応する前提です。Discord自体が失敗した場合は管理者にメールが届きます（[14.2](#142-notifyservicediscordslack)）。

### 3.3 スタッフの1日の運用イメージ

1. Discordの「#予約状況」に新規予約の通知が届く → 承認リンクを開いて内容を確認し、必要なら修正して「承認して確定」
2. 受けられない場合は、管理者画面で該当の仮予約を開き「却下」（お客様にLINEでお断りが届く）
3. 電話・店頭・InstagramのDMなどで受けた予約は、管理者画面の「予約を追加」で登録
4. 毎朝9時台に、翌日の確定予約のリマインドがDiscordに届く（お客様にもLINE/メールで届く）
5. キャンセルの連絡はLINEのトーク（公式アカウントのチャット）で受け、管理者画面で「キャンセルにする」

### GASのファイル構成の約束

- GASの `.js` ファイルはすべて**同じグローバルスコープ**で読み込まれます（`import`/`export`はない）。ファイルの読み込み順に依存しないよう、トップレベルでは関数・定数・名前空間の定義だけを行います
- `SheetService` / `CalendarService` / `NotifyService` / `LineService` は、即時関数で作った**名前空間オブジェクト**です。中の関数は `google.script.run` から呼べません
- `Code.js` の汎用ヘルパー（`formatDateTimeForDisplay_()`、`sendEmail_()`、`getHolidayMap_()`、`getClosedReason_()`、`assertEditorRun_()` など）は他のファイルからそのまま呼ばれています。名前を変えるときは全ファイルを検索してください
- 関心事ごとに分ける方針です（シート＝SheetService、カレンダー＝CalendarService、Discord＝NotifyService、LINE＝LineService、定期実行＝Trigger、それ以外の業務ロジック＝Code）

# 第2部 データとインターフェース

## 5. データモデル（スプレッドシート）

スプレッドシートIDはスクリプトプロパティ `SPREADSHEET_ID` で指定します。台帳の名前は「SPACE予約管理」です。

### 5.1 シート「予約一覧」

1行目がヘッダー、2行目以降が1行1予約です。列順は `SheetService.js` の `HEADERS` 定数で決まっています。

| # | 列名 | 型・形式 | 書き込むタイミング | 内容・例 |
|---|---|---|---|---|
| 1 | ID | UUID文字列 | 登録時 | `Utilities.getUuid()`。承認リンクにも使う。例: `3f1c…-…` |
| 2 | ステータス | `仮予約` / `確定` / `キャンセル` | 登録・承認・キャンセル時 | |
| 3 | 予約日時 | `yyyy-MM-ddTHH:mm:ss`（シート上でDateになることもある） | 登録・承認時 | 開始日時。終了時刻は持たない。例: `2026-11-20T18:00:00` |
| 4 | 人数 | 数値 | 登録・承認・人数変更時 | 1〜15 |
| 5 | スペース | `スタンディング・スペース` / `ラウンジ・スペース` / 空 | 登録・承認時 | 管理画面の代理登録では「未定（空）」もある |
| 6 | 飲み放題 | `あり` / `なし` | 登録・承認時 | |
| 7 | ご利用履歴 | `初めて` / `利用したことがある` | 登録・承認時 | |
| 8 | 氏名（カタカナ） | 文字列 | 登録・承認時 | フォームでは「セイ メイ」を半角スペースでつなぐ。カタカナは案内のみで強制しない |
| 9 | 電話番号 | 文字列 | 登録・承認時 | 先頭の0が消えないよう `'` 付きで保存。形式チェックなし |
| 10 | メールアドレス | 文字列 / 空 | 登録・承認時 | 正規化済み |
| 11 | 備考 | 文字列 | 登録・承認時 | カレンダー予定の説明欄にも入る |
| 12 | LINE UserId | `U`で始まる33文字 / 空 | 登録時 | LIFFで取得。管理画面からの登録・LIFF未ログインでは空 |
| 13 | 登録日時 | Date | 登録時 | 行を追加した日時 |
| 14 | カレンダーイベントID | 文字列 / 空 | 承認時 | `CalendarEvent.getId()` の値。キャンセル・人数変更で使う |

#### 読み書きの実装

| 処理 | 実装 | 補足 |
|---|---|---|
| 追加 | `sheet.appendRow([...])` | 末尾に1行追加 |
| 1件の検索 | `getDataRange().getValues()` で全行を読み、1列目（ID）が一致する行を探す | 行数に比例して遅くなる |
| 更新 | 列名から列番号を引き、`getRange(row, col).setValue()` を列ごとに呼ぶ | `HEADERS` にない列名は無視される |
| 一覧 | 全行を `{列名: 値}` のオブジェクトに変換 | 管理者画面に全件を渡す |
| 削除 | しない（ステータスで論理削除） | アーカイブだけ行を物理削除する |

#### ヘッダー行の自動修復（注意）

`getSheet_()` はシートを開くたびに次のことをします。

1. シート「予約一覧」がなければ作る
2. 空なら `HEADERS` を1行目に書く
3. 1行目が `HEADERS` と1文字でも違えば、**1行目を `HEADERS` で上書き**する（データ行は動かさない）

そのため `HEADERS` の途中に列を挿入すると、既存データと見出しがずれます。列を増やすときは**末尾に追加**してください（[21.1](#211-予約の項目を追加する)）。シートを手で編集して見出しを変えても、次のアクセスで元に戻ります。

#### セルの書き込み前の処理（`sanitizeCell_()`）

外部からの入力は必ず `sanitizeCell_()` を通してから書き込みます。文字列で、次のどちらかに当たる場合は先頭に `'` を付けて「文字列として」保存します。

| 条件 | 理由 |
|---|---|
| 先頭が `=` `+` `-` `@` タブ `\r` | 数式として解釈されるのを防ぐ（数式インジェクション対策） |
| `0` の後に数字が続く（例: `090…`） | 数値に変換されて先頭の0が消えるのを防ぐ |

数値（人数など）やDateはそのまま書き込みます。

### 5.2 シート「予約一覧_archive」

`archiveOldReservations()` が、予約日時が**180日より前**の「確定」「キャンセル」の行をここへ移します（列構成は同じ。初回に自動作成）。「仮予約」は何日経っても移しません。管理者画面・空き状況・リマインドはメインシートしか見ないため、アーカイブした予約は画面に出なくなります。予約日時が日付として読めない行も移しません。

### 5.3 スクリプトプロパティに保存される実行時データ

設定値以外に、次のデータもスクリプトプロパティに書き込まれます（スクリプトプロパティ全体の上限は約500KB）。

| キー | 内容 | 書き込む処理 |
|---|---|---|
| `ADMIN_EMAILS` / `VIEWER_EMAILS` | カンマ区切りのメールアドレス | 「ユーザーを管理」 |
| `LOGIN_SESSION_<64桁hex>` | `{"email": "...", "expiresAt": <ミリ秒>}` | ログインリンクの発行 |
| `EMAIL_QUOTA_ALERT_DATE` | `yyyy-MM-dd`。メール残数の警告を最後に出した日 | `checkEmailQuota_()` |

### 5.4 キャッシュ（CacheService）

| キー | 値 | 有効期間 | 用途 |
|---|---|---|---|
| `JP_HOLIDAYS_<開始日>_<終了日>` | `{"yyyy-MM-dd": "祝日名"}` のJSON | 6時間 | 祝日カレンダーの読み込み回数を減らす |
| `LOGIN_LINK_SENT_<email>` | `'1'` | 60秒 | ログインリンクの連打防止 |

## 6. GAS Webアプリのインターフェース

GASのWebアプリは公開URLを1つしか持てないため、クエリパラメータで処理を分けています。

### 6.1 HTTPエンドポイント

| メソッド | パラメータ | 処理 | 応答 |
|---|---|---|---|
| GET | なし | 空き状況を返す | JSON |
| GET | `?page=approval&id=<予約ID>` | 承認画面 | HTML（`ApprovalPage.html`） |
| GET | `?page=admin` | 管理者画面（権限がなければログイン画面） | HTML（`AdminPage.html` / `AdminLoginPage.html`） |
| GET | `?page=admin&session=<トークン>` | 社外アカウントのログインリンク | 同上 |
| POST | 本文＝予約JSON | 仮予約を登録 | JSON |

`?page=approval` で `id` がない場合や、`page` が上記以外の場合は、空き状況のJSONが返ります。

#### GET 空き状況

今日から予約可能な最終日（[7章](#7-業務ルール予約受付の条件)）までの日付ごとの配列を、日付の昇順で返します。

```json
[
  { "date": "2026-11-09", "available": false, "closed": true,  "closedReason": "日曜定休" },
  { "date": "2026-11-10", "available": true,  "closed": false, "closedReason": "" },
  { "date": "2026-11-23", "available": false, "closed": true,  "closedReason": "祝日（勤労感謝の日）" }
]
```

| 項目 | 型 | 内容 |
|---|---|---|
| `date` | `yyyy-MM-dd` | 日本時間の日付 |
| `available` | boolean | 定休日ではなく、かつ**その日の「確定」予約の合計人数**が15人未満なら `true` |
| `closed` | boolean | 定休日（日曜・祝日）なら `true` |
| `closedReason` | 文字列 | `日曜定休` / `祝日（<祝日名>）` / 空文字 |

- 仮予約・キャンセルは人数に数えない。スペース別・時間帯別の判定はしない（あくまで目安）
- シートの読み込みに失敗した場合は、エラーをログに残して「予約0件」として計算する（全日空きに見える）

#### POST 仮予約

**CORS対策**: GASのWebアプリはプリフライト（OPTIONS）を処理できないため、フロントは `Content-Type: text/plain;charset=utf-8` でJSON文字列を送ります。`application/json` にするとブラウザがプリフライトを送り、失敗します。GAS側は `JSON.parse(e.postData.contents)` で受け取ります。GASの応答はリダイレクト（`script.googleusercontent.com`）を経由しますが、`fetch` は自動で追従します。

リクエスト本文:

```json
{
  "datetime": "2026-11-20T18:00:00",
  "headcount": 4,
  "space": "ラウンジ・スペース",
  "drink": "あり",
  "usageHistory": "初めて",
  "name": "ヤマダ タロウ",
  "phone": "09012345678",
  "email": "taro@example.com",
  "note": "",
  "userId": "Uxxxxxxxx..."
}
```

| 項目 | 必須 | サーバー側の検証（チェック順） |
|---|---|---|
| （本文全体） | ○ | JSONとして読めること |
| datetime / name / phone | ○ | 3つとも空でないこと |
| headcount | — | 指定されていれば1〜15の整数 |
| datetime | — | 日付部分（先頭10文字）が `yyyy-MM-dd` 形式なら、予約可能な最終日を超えていないこと |
| datetime | — | 日付として読めるなら、定休日でないこと |
| email | — | 正規化したうえで、空でなければ形式チェック |
| space / drink / usageHistory / note / userId | — | 検証なし（そのまま保存） |

応答: 成功時 `{"success": true, "id": "<予約ID>"}`、失敗時 `{"success": false, "error": "<メッセージ>"}`。HTTPステータスはどちらも200です。エラーメッセージは[付録C](#付録c-エラーメッセージ一覧)。

curlでの確認例（本番のシートに仮予約が入るので、確認後はキャンセルしてください）:

```bash
curl -sL -H 'Content-Type: text/plain;charset=utf-8' -d '{"datetime":"2026-11-20T18:00:00","headcount":2,"name":"テスト","phone":"0000000000"}' "$GAS_ENDPOINT_URL"
```

### 6.2 `google.script.run` で呼ぶサーバー関数

承認画面・管理者画面・ログイン画面のJSから呼ばれる関数です。権限が必要な関数は、最後の引数で `sessionToken`（社外アカウントのログイントークン。社内アカウントなら `null`）を受け取ります。戻り値はすべて `{ success: boolean, error?: string, ... }` 形式で、**業務上のエラーは例外ではなく `success: false` で返します**（画面側は `withSuccessHandler` で `success` を見て、`withFailureHandler` は通信エラーなど想定外のときだけ）。

| 関数 | 呼び出し元 | 権限チェック | 成功時の戻り値 | 内容 |
|---|---|---|---|---|
| `approveReservation(id, editedData)` | 承認画面・管理者画面 | **なし**（[22章](#22-既知の制約注意点)） | `{success}` | 承認して確定 |
| `cancelReservation(id, sessionToken)` | 管理者画面 | 管理者 | `{success}` | 却下・キャンセル |
| `updateReservationHeadcount(id, headcount, sessionToken)` | 管理者画面 | 管理者 | `{success, reservation}` | 人数変更 |
| `createReservationByAdmin(data, sessionToken)` | 管理者画面 | 管理者 | `{success, reservation}` | 予約の代理登録 |
| `getAllUsers(sessionToken)` | 管理者画面 | 管理者 | `{success, users}` | 管理者・閲覧者の一覧 |
| `addUser(email, role, sessionToken)` | 管理者画面 | 管理者 | `{success, users}` | ユーザー追加 |
| `removeUser(email, sessionToken)` | 管理者画面 | 管理者 | `{success, users}` | ユーザー削除 |
| `setUserRole(email, role, sessionToken)` | 管理者画面 | 管理者 | `{success, users}` | 権限の切り替え |
| `requestAdminLoginLink(email)` | ログイン画面 | なし（仕様） | `{success, message}` | ログインリンクをメール送信 |
| `logoutAdminSession(sessionToken)` | 管理者画面 | なし（仕様） | `{success}` | セッショントークンを削除 |

- `users` は `[{email, role: 'admin' | 'viewer'}]`（管理者が先、それぞれ登録順）
- `reservation` はシートの1行を `{列名: 値}` にしたもの。`google.script.run` は `Date` を返せないため `JSON.parse(JSON.stringify(...))` でISO文字列（UTC表記）にしてから返す
- `createReservationByAdmin` は、行の追加には成功して確定処理だけ失敗した場合 `{success: false, error, reservation}` を返す（画面は一覧に反映したうえでエラーを表示）

#### `approveReservation` の `editedData`

承認画面のフォームの値（`{列名: 値}`）です。反映できるのは次の9列だけです（`EDITABLE_FIELDS` による許可リスト）。

`予約日時, 人数, スペース, 飲み放題, ご利用履歴, 氏名（カタカナ）, 電話番号, メールアドレス, 備考`

`ID`・`ステータス`・`LINE UserId`・`登録日時`・`カレンダーイベントID` は送られてきても無視します。管理者画面の「承認して確定」は `editedData` に `{}` を渡し、シートの内容のまま確定します。**人数の範囲チェックは承認時には行いません**（[22章](#22-既知の制約注意点)）。

#### `createReservationByAdmin` の `data`

| 項目 | 必須 | 検証・変換 |
|---|---|---|
| status | — | `仮予約` ならその通り、それ以外はすべて `確定` |
| datetime | ○ | `yyyy-MM-ddTHH:mm` または `yyyy-MM-ddTHH:mm:ss`。秒がなければ `:00` を補う |
| headcount | ○ | 1〜15の整数 |
| name | ○ | 前後の空白を除いて空でないこと |
| email | — | 正規化 → 空でなければ形式チェック |
| space / drink / usageHistory / phone / note | — | 前後の空白を除くだけ |

期間・定休日の制限はありません（特別対応の登録用）。`userId` は常に空です。

### 6.3 排他制御（`withReservationLock_`）

予約データを読んで判定して書き込む処理（`doPost`、承認、キャンセル、人数変更、代理登録）は、`withReservationLock_(fn)` でスクリプト全体のロック（`LockService.getScriptLock()`）を取ってから `fn` を実行します。

- 最大10秒待っても取れなければ「只今他の予約処理が混み合っています。少し時間をおいて再度お試しください。」というエラーにする
- `fn` が例外を投げても `finally` でロックを解放する
- 外部通知（Discord・LINE・メール）は時間がかかるので、なるべくロックの外で送る。カレンダー操作はシートとの整合をとるためロックの中で行う
- `createReservationByAdmin` の「確定」は、ロックの中で行を追加 → ロックを解放 → `approveReservation` が改めてロックを取る、の順。GASのスクリプトロックは同じ実行の中でも二重に取れないため、入れ子にしないこと

## 7. 業務ルール（予約受付の条件）

| ルール | 値 | 定義場所 | 予約フォーム | 管理画面からの追加 |
|---|---|---|---|---|
| 予約できる期間 | 今日から**3か月後の同じ日**まで（その月に同じ日がなければ月末） | `BOOKING_MONTHS_AHEAD`（Code.js） | 適用 | 制限なし |
| 定休日 | **日曜・祝日** | `getClosedReason_()`（Code.js） | 適用（「休」表示で選べない） | 制限なし（特別対応用） |
| 1件の人数 | **1〜15名** | `MAX_HEADCOUNT`（Code.js / calendar.js） | 適用 | 適用（人数変更も同じ） |
| 1日の受付目安 | 確定予約の合計が**15名**に達したら「－」（受付不可）表示 | `DAILY_CAPACITY`（SheetService.js） | 表示のみ（サーバーでは拒否しない） | — |
| 時間の選択肢 | 15:00〜21:00 の30分刻み（13個） | calendar.js | 表示のみ（サーバーでは検証しない） | 15分刻みで任意 |
| 確定時のカレンダー予定 | 開始から**1時間**の予定 | CalendarService.js | — | — |
| ログインの有効期間 | 7日 | `LOGIN_SESSION_DAYS`（Code.js） | — | — |
| アーカイブ | 予約日時が180日より前の確定・キャンセル | `ARCHIVE_AFTER_DAYS`（SheetService.js） | — | — |

### 7.1 予約できる期間の計算

`getLastBookableDateStr_()`:

```
今日 = 2026-11-09 → 最終日 = 2027-02-09
今日 = 2026-11-30 → 最終日 = 2027-02-28（2月30日はないので月末）
今日 = 2026-12-31 → 最終日 = 2027-03-31
```

`getBookingDaysAhead_()` は今日から最終日までの日数（両端を含む）で、空き状況JSONの件数になります。上の1つ目の例では93件です。

### 7.2 定休日の判定

`getClosedReason_(dateStr, holidays)`:

1. `dateStr` が `yyyy-MM-dd` として読めなければ空文字（営業日扱い）
2. 曜日が日曜なら `日曜定休`
3. `holidays[dateStr]` があれば `祝日（<祝日名>）`
4. それ以外は空文字

祝日は `CalendarService.getJapaneseHolidays(開始, 終了)` が、Googleの公開カレンダー「日本の祝日」（`ja.japanese#holiday@group.v.calendar.google.com`）から取得します。

- 2024年頃から節分・ひな祭り・七五三・クリスマスなど祝日でない行事も同じカレンダーに載るようになったため、**説明欄が「祝日」で始まるもの**（国民の祝日・振替休日・国民の休日）だけを祝日として扱う
- 結果は期間ごとに6時間キャッシュする
- 取得に失敗した場合は `getHolidayMap_()` が空のオブジェクトを返し、日曜だけを定休日とみなす（予約受付を止めないため）
- お盆・年末年始などの臨時休業には対応していない（[21.4](#214-定休日臨時休業を変える)）

### 7.3 空き状況の判定は「目安」

- その日の**確定**予約の人数を合計し、15人未満なら空きあり
- スペース（スタンディング／ラウンジ）も時間帯も区別しない
- 仮予約は数えないので、同じ日に申し込みが集中することがある
- `doPost` は定員を確認しない（表示上「－」の日でも、直接POSTすれば仮予約は入る）
- 最終判断はスタッフが承認画面で行う

### 7.4 入力値の正規化と検証

**メールアドレス**（`normalizeEmail_()` → `isValidEmail_()`）:

1. 全角の `！`〜`～`（全角英数記号）を半角に変換（`＠` → `@`、`．` → `.` など）
2. 全角スペースを半角に変換
3. 前後の空白を除く
4. 正規表現 `EMAIL_PATTERN` で検証

```
/^[A-Za-z0-9.!#$%&'*+\/=?^_`{|}~-]+@(?:[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?\.)+[A-Za-z]{2,}$/
```

- 「@」の前: 英数字と記号を広く許可。docomo・auの古いアドレスに実在する `..` や `@` 直前の `.` も通す
- ドメイン: 英数字とハイフンのラベルを `.` でつなぎ、英字2文字以上のTLDで終わる。`gmail.con` のような誤字は通ってしまう
- 使っている箇所: 予約受付（`doPost`）・承認時の編集・代理登録・ユーザー追加・ログインリンク要求の5か所
- 同じ正規表現と正規化が `frontend/js/reserve-form.js` にもある。**変えるときは両方そろえる**

**人数**（`isValidHeadcount_()`）: `Number()` に変換して、整数かつ1〜15。`"4"` のような文字列も通る。

**電話番号**: 必須チェックのみで、形式は検証しない（ハイフンあり・なし、海外番号などをそのまま受ける）。

## 8. 日付・時刻・タイムゾーンの扱い

GASプロジェクトのタイムゾーンは `Asia/Tokyo` です。日付まわりは不具合が出やすいので、次の約束を守ってください。

| 場面 | 扱い |
|---|---|
| フロントから届く予約日時 | `yyyy-MM-ddTHH:mm:ss`（タイムゾーンなし）の**文字列**。日本時間の意味 |
| シートへの保存 | その文字列を書き込む。シートの設定によってはDate型に変換される。どちらでも読めるようにしてある |
| 日付だけを取り出す | `SheetService.formatDateOnly_()`（`Utilities.formatDate(…, 'Asia/Tokyo', 'yyyy-MM-dd')`）。Date・文字列どちらにも対応 |
| 表示用の整形 | `formatDateTimeForDisplay_()` →「11月20日(金) 18:00」 |
| 定休日の曜日判定 | `Date.UTC(y, m-1, d).getUTCDay()`。タイムゾーンの影響を受けない |
| `doPost` の日付チェック | `new Date('yyyy-MM-ddT00:00:00+09:00')` と明示的に+09:00を付ける |
| カレンダー予定の開始 | `new Date(予約日時)`。タイムゾーンなしの文字列はスクリプトのタイムゾーン（日本時間）として解釈される |
| 管理者画面（ブラウザ） | 予約日時はJSON経由でUTCのISO文字列（例: `2026-11-20T09:00:00.000Z`）になることがある。`new Date()` してブラウザのローカル時刻で表示するので、日本のPCなら正しく出る |
| 予約フォーム（ブラウザ） | カレンダーの日付は `new Date(年, 月, 日)` のローカル時刻で計算し、`isoDate()` で文字列にする |

# 第3部 処理の詳細

## 9. 処理シーケンス（関数ごとの手順）

### 9.1 お客様の予約申し込み（`doPost`）

```
フロント                         GAS doPost                          外部
  │ POST text/plain JSON ─────▶ │
  │                              │ 1. JSON.parse（失敗→invalid request）
  │                              │ 2. 必須チェック（datetime, name, phone）
  │                              │ 3. 人数チェック（指定時のみ）
  │                              │ 4. 期間チェック（最終日を超えていないか）
  │                              │ 5. 定休日チェック（祝日カレンダー参照）
  │                              │ 6. メールの正規化・形式チェック
  │                              │ ┌ロック─────────────────────┐
  │                              │ │7. シートに仮予約の行を追加   │──▶ スプレッドシート
  │                              │ └─────────────────────────┘
  │                              │ 8. Discordへ新規予約通知＋承認リンク ──▶ Discord
  │                              │ 9. メールアドレスがあれば受付メール ──▶ MailApp
  │                              │10. userIdがあればLINEで受付通知 ──▶ LINE
  │                              │    （失敗したらDiscordへ⚠️）
  │ ◀── {success:true, id} ──── │
```

- 1〜6で失敗すると何も書き込まずに `success: false` を返す
- 7以降で例外が起きた場合も `success: false`。ただし7が成功していれば仮予約は残る
- 8〜10の失敗は応答に影響しない（各サービス内でログ・警告）

### 9.2 承認（`approveReservation`）

1. `id` が空ならエラー
2. ロックを取る
3. シートから予約を読む。なければエラー
4. ステータスが「確定」なら何もせず成功を返す（二重実行防止）。「キャンセル」ならエラー（キャンセル済みを確定に戻さない）
5. `editedData` から許可された9列だけを取り出す。メールアドレスが含まれていれば正規化・形式チェック
6. シートの値に編集内容を重ねた `confirmed` を作り、ステータス「確定」と9列をシートに書き込む
7. カレンダーに予定を作成し、イベントIDをシートに保存。失敗したらDiscordへ⚠️（処理は続行）
8. ロックを解放
9. Discordへ確定報告
10. LINE UserIdがあればLINEで確定通知。失敗したらDiscordへ⚠️「お客様に電話等で確認をお願いします」
11. メールアドレスがあれば確定メール
12. `{success: true}` を返す

例外はすべて `catch` して `{success: false, error}` にします。

### 9.3 却下・キャンセル（`cancelReservation`）

1. 管理者でなければ「アクセス権がありません」
2. `id` が空ならエラー
3. ロックの中で:
   - 予約を読む。なければエラー
   - すでに「キャンセル」なら何もせず成功（二重実行防止）
   - 元のステータスが「確定」かどうかを記録（`wasConfirmed`）
   - ステータスを「キャンセル」に更新
   - 元が確定でカレンダーイベントIDがあれば予定を削除。失敗したらDiscordへ⚠️
4. Discordへ「確定済みの予約がキャンセルされました」または「仮予約が却下されました」
5. LINE UserIdがあればLINEで通知（文面は `wasConfirmed` で変わる）。失敗したらDiscordへ⚠️
6. メールは送らない

### 9.4 人数変更（`updateReservationHeadcount`）

1. 管理者チェック、`id` チェック、人数の範囲チェック（1〜15）
2. ロックの中で:
   - 予約を読む。なければエラー。「キャンセル」ならエラー
   - 人数が同じなら何もしない（`changed: false`、通知もしない）
   - シートの人数を更新
   - 確定済みでカレンダーイベントIDがあれば予定のタイトルを更新。失敗したらDiscordへ⚠️
3. 変更があればDiscordへ「人数: 4名 → 6名」
4. 更新後の予約を返す（画面の表示を更新するため）

お客様への自動連絡はしません（お客様からの依頼で変更する想定のため）。

### 9.5 管理画面からの予約追加（`createReservationByAdmin`）

1. 管理者チェック、入力の検証（[6.2](#createreservationbyadmin-の-data)）
2. ロックの中で、シートに仮予約の行を追加（`userId` は空）
3. ステータスが「確定」なら `approveReservation(id, {})` を呼ぶ（カレンダー登録・Discord確定報告・確定メール）。失敗したら「予約は仮予約として登録されましたが、確定処理に失敗しました…」
4. 「仮予約」ならDiscordへ「【管理画面から追加】新規予約リクエストがありました…」と承認リンク
5. シートから読み直した予約を返す

### 9.6 前日リマインド（`sendReminders`）

1. ガード（エディタまたはこのプロジェクトのトリガーからの実行のみ）
2. 明日の日付（日本時間）を求める
3. シートから、ステータス「確定」で予約日が明日の予約をすべて取り出す
4. 1件ずつ:
   - LINE UserIdがあればLINEでリマインド。失敗したらDiscordへ⚠️
   - メールアドレスがあればリマインドメール
   - Discordへ「【リマインド】明日のご予約」
5. 途中で例外が起きたらログに残して終了（それ以降の予約には送られない）

### 9.7 管理者画面を開く（`renderAdminPage_`）

1. `getUserRole_(session)` で権限を判定
2. 権限がなければログイン画面を返す。`session` が付いていた場合は「有効期限が切れた」旨を表示
3. 権限があれば、全予約・ロール・セッショントークンをテンプレートに埋め込んで管理者画面を返す
   - Googleアカウントで認証できた場合（sinnovation.jpの社員）は、トークンは画面に渡さない（`null`）

### 9.8 ログインリンクの発行（`requestAdminLoginLink`）

1. メールアドレスを正規化。形式が不正なら「正しいメールアドレスを入力してください」
2. 登録されていなければ、**メールを送らずに**成功と同じ応答を返す（ログには残す）
3. 同じアドレスに60秒以内に送っていれば、送らずに同じ応答
4. 期限切れのセッションを掃除
5. 64桁のトークン（UUID2つ分のhex）を作り、`LOGIN_SESSION_<トークン>` に `{email, expiresAt}` を保存
6. `<WEB_APP_URL>?page=admin&session=<トークン>` をメールで送信
7. 連打防止のフラグをキャッシュに60秒置く
8. 「登録済みのメールアドレスであれば、ログイン用のリンクを送信しました。メールをご確認ください。」を返す

`reserveState` の中身:

### 10.4 LIFFの初期化（`liff-init.js`）

1. `LIFF_ID` が `'YOUR_LIFF_ID'` なら開発用のダミーモード（`currentUserId = 'dummy-user-id'`）
2. `liff.init({ liffId })`
3. 未ログインなら `liff.login({ redirectUri: location.href })` でログインさせる（LINEアプリ外のブラウザで開いた場合もLINEログイン画面に飛ぶ）
4. `liff.getProfile()` の `userId` を `currentUserId` に入れる
5. 途中で失敗したらコンソールにエラーを出すだけ（フォームは使える。LINE通知は届かない）

### 10.5 カレンダーの描画（`calendar.js`）

1. `fetchAvailability()` で空き状況を取得（失敗時・未設定時はダミーデータ）
2. 配列から `availabilityMap[date] = available`、`closedMap[date] = closedReason` を作る
3. 配列の最後の日付を `maxDate` とし、その月まで「›」で進める。今月より前には戻れない
4. 各日付のマスの状態:

| 状態 | 条件 | クラス | 表示 | 選択 |
|---|---|---|---|---|
| 定休日 | 範囲内で、`closedMap` にあるか日曜 | `is-closed` | 休（ホバーで理由） | 不可 |
| 範囲外 | 今日より前か `maxDate` より後 | `is-past` | － | 不可 |
| 受付不可 | 範囲内で `available !== true` | `is-past` | － | 不可 |
| 空きあり | 上記以外 | `is-available` | ○ | 可 |

5. 人数のプルダウンは1〜`MAX_HEADCOUNT`名、時間は15:00〜21:00の30分刻み
6. 日付・人数・時間がそろうと「次へ」が押せるようになる

### 10.6 入力チェックと送信（`reserve-form.js`）

| タイミング | チェック |
|---|---|
| Step2「次へ」 | スペースを選ぶまでボタンが無効 |
| Step3 メール欄からフォーカスが外れたとき | 正規化して欄に書き戻し、形式が不正ならエラー表示（一度エラーになった後は入力のたびに再チェック） |
| Step3「予約前の最終確認へ」 | セイ・メイ・電話番号が空なら `alert`、メールが不正なら欄にフォーカス |
| Step4 | 入力値を `escapeHtml()` でエスケープして一覧表示（XSS対策） |
| Step4「この内容で登録する」 | ボタンを無効にして「送信中...」→ POST → 成功なら完了画面、失敗なら `alert` してボタンを戻す |

送信するJSON: `datetime` は `<dateISO>T<time>:00`、`name` は `<セイ> <メイ>`、`userId` は `currentUserId`。

### 10.7 開発用のダミーモード

- `LIFF_ID` が `'YOUR_LIFF_ID'` のままなら、LIFFを初期化しない
- `GAS_ENDPOINT_URL` が空なら、空き状況はダミーデータ、送信はコンソール出力のみで完了画面へ

ローカルで確認するときは `frontend/` を静的サーバーで開きます（LIFFの機能はLINEアプリ内でのみ有効）。

```bash
cd frontend && python3 -m http.server 8000
```

## 11. 承認画面

`?page=approval&id=XXX`。`renderApprovalPage_(id)` がシートから予約を読み、`reservationId` と `reservation` をテンプレートに埋め込みます。

- Discordの新規予約通知に載っているリンクから開く。予約IDを知っていれば誰でも開ける（ログイン不要）
- フォームの各入力欄の `name` は**シートの列名そのもの**（`氏名（カタカナ）` など）。読み込み時に同じ名前の列の値を入れ、送信時はフォームの全項目を `{列名: 値}` にして `approveReservation(id, editedData)` に渡す
- 編集できる項目: 氏名・電話番号・予約日時・人数・飲み放題・スペース・ご利用履歴・メールアドレス・備考（すべて自由入力のテキスト欄）
- 成功すると「確定しました」の画面に切り替わる。失敗したらエラーを表示してボタンを戻す
- 予約が見つからなければ「予約が見つかりませんでした」と表示
- 仮予約以外（確定済み・キャンセル済み）はフォームを出さず、その旨を表示する
- 予約日時の欄には、シートの値がDateならISO文字列（UTC）で表示される。そのまま承認すれば同じ日時として保存される

## 13. 認証・権限

### 13.1 ロール

| ロール | 登録先（スクリプトプロパティ） | できること |
|---|---|---|
| `admin`（管理者） | `ADMIN_EMAILS` | すべての操作 |
| `viewer`（閲覧者） | `VIEWER_EMAILS` | 管理者画面の閲覧のみ |

| 関数 | 内容 |
|---|---|
| `getUserRole_(sessionToken)` | ①Googleアカウントのメールアドレス、②セッショントークンのメールアドレス、の順に `getRoleForEmail_()` で照合し、`'admin'` / `'viewer'` / `null` を返す |
| `getRoleForEmail_(email)` | 大文字・小文字を区別せずに一覧と照合。両方に載っていれば `admin` が優先 |
| `isAuthorizedAdmin_(sessionToken)` | `admin` のときだけ `true`。操作系の関数はすべてこれで保護する |
| `isAuthorizedViewer_(sessionToken)` | `admin` か `viewer` なら `true`（現在は未使用） |

- 管理者が0人になる操作（最後の管理者の削除・閲覧者への降格）は拒否する（ロックアウト防止）
- 同じアドレスを二重に登録しようとすると「既に登録されています」
- `ADMIN_EMAILS` は、Discord通知が失敗したときのフォールバックメールの宛先も兼ねる

### 13.2 本人確認の2つの方法

1つのWebアプリのデプロイで、予約受付用と管理者用を兼ねています（別デプロイは不要）。

**① sinnovation.jp（スクリプト所有者と同じWorkspaceドメイン）のアカウント**

`Session.getActiveUser().getEmail()` でメールアドレスが取れるので、Googleにログインしていればそのまま管理者画面が開きます。画面にトークンは渡しません。

**② Gmailなど社外のアカウント**

「自分として実行」のWebアプリでは、`Session.getActiveUser()` は所有者と同じドメインのユーザーにしかメールアドレスを返しません（Googleの仕様。GASプロジェクトを共有しても変わらないことを2026-10-05に確認済み）。そのため、メールでリンクを送る方式（マジックリンク）で本人確認します。

```
1. ?page=admin を開く → 権限なし → ログイン画面（AdminLoginPage.html）
2. メールアドレスを入力 → requestAdminLoginLink(email)（手順は9.8）
3. メールのリンク ?page=admin&session=<トークン> を開く
     → トークンから email を引き、ADMIN_EMAILS / VIEWER_EMAILS と照合
4. 画面の操作のたびに sessionToken をサーバーへ送り、毎回照合し直す
```

| 性質 | 内容 |
|---|---|
| トークン | 64桁の16進数（UUID2つ分）。形式が違えば即無効 |
| 有効期間 | 7日（延長なし） |
| 権限の変更 | 毎回照合し直すので、ユーザー登録を削除すればそのトークンも**即座に**無効 |
| ログアウト | `logoutAdminSession()` がトークンを削除 |
| 期限切れの掃除 | アクセス時にそのトークンを削除。新しいリンクの発行時に全セッションを掃除 |
| 登録の有無の秘匿 | 未登録アドレスにはメールを送らず、応答は同じ |
| 連打防止 | 同じアドレスへの送信は1分に1回まで |
| 注意 | リンクを他人に転送すると、その人も7日間ログインできる |

### 13.3 WebアプリのURL（`WEB_APP_URL`）

ログインリンクやDiscordの承認リンクに載せるURLは `getWebAppUrl_()` で作ります。

1. スクリプトプロパティ `WEB_APP_URL` があれば、`?` 以降を除いて使う
2. なければ `ScriptApp.getService().getUrl()` の `/a/macros/<ドメイン>/` を `/macros/` に直して使う

`getUrl()` は、実際には開けないURLや社内ドメイン限定の `/a/macros/<ドメイン>/` 形式を返すことがあり、社外の人が開けない恐れがあるため、1を推奨しています。値は「デプロイを管理」に表示される `https://script.google.com/macros/s/〜/exec` 形式です（`/dev` のURLはテスト用で、編集権限のない人は開けません）。

## 14. 通知

### 14.1 送信先と内容

| 宛先 | 手段 | 送るタイミング |
|---|---|---|
| スタッフ | Discord（`DISCORD_WEBHOOK_URL`）またはSlack（`SLACK_WEBHOOK_URL`） | 新規予約（承認リンク付き）、確定、却下・キャンセル、人数変更、前日リマインド、各種失敗の警告、メール残数の警告 |
| お客様（LINE連携あり） | LINE Messaging API のプッシュ送信 | 仮予約受付、確定、却下・キャンセル、前日リマインド |
| お客様（メールあり） | `MailApp`（差出人名「oO SPACE」） | 仮予約受付、確定、前日リマインド（却下・キャンセルはメールなし） |
| 管理者 | `MailApp` | Discord通知が最終的に失敗したときのフォールバック、ログインリンク |

文面はすべて[付録B](#付録b-通知文面一覧)。

**Discordに個人情報を載せない**: Discord（Slack）への通知には、お客様の**電話番号・メールアドレスを含めません**（すべての通知が対象）。載せるのは氏名・日時・人数・スペース・飲み放題・ご利用履歴・備考までです。電話番号などは承認画面・管理者画面で確認します。通知文を追加・変更するときもこのルールを守ってください。

### 14.2 NotifyService（Discord/Slack）

`NotifyService.send(message)` だけでDiscordとSlackの両方に対応します。例外は投げません。

| 項目 | 内容 |
|---|---|
| 送信先の選択 | `DISCORD_WEBHOOK_URL` を優先し、なければ `SLACK_WEBHOOK_URL` |
| 形式の判定 | URLが `https://(サブドメイン.)discord.com` / `discordapp.com` の `/api/webhooks/` なら Discord 形式 `{content, allowed_mentions: {parse: []}}`、それ以外は Slack 形式 `{text}` |
| 文字数 | Discord は1メッセージ2000文字まで。超える分は切り詰めて「…（以下省略）」 |
| メンションの抑止 | `allowed_mentions: {parse: []}` で、氏名や備考に `@everyone` が入力されてもメンションが飛ばない |

**再送とフォールバック**:

| 結果 | 対応 |
|---|---|
| 2xx | 成功 |
| 429（レート制限） | `Retry-After` ヘッダーか本文の `retry_after` の秒数（1〜15秒、不明なら5秒）待って再送 |
| 5xx・通信エラー | 2秒→4秒待って再送 |
| 400/401/403/404など | 再送しても直らないので、すぐあきらめる |
| 3回失敗 / 再送不可 / URL未設定 | `ADMIN_EMAILS` 全員に「【oO SPACE】Discord通知の送信に失敗しました」メール（失敗理由と本来の通知内容入り） |

フォールバックメールの「理由」には、ステータスコードごとの説明が入ります（例: 404「Webhookが見つかりません（Discord側でWebhookが削除された可能性があります…）」）。

### 14.3 LineService（LINE Messaging API）

アクセストークンは次の優先順で取得します（`getAccessToken_()`）。

1. スクリプトプロパティ `LINE_CHANNEL_ACCESS_TOKEN`（長期トークン）があればそれを使う
2. なければ `LINE_CHANNEL_ID` と `LINE_CHANNEL_SECRET` で、`POST https://api.line.me/oauth2/v3/token`（`grant_type=client_credentials`）から**送信のたびに**15分有効なステートレストークンを取得する（現在の本番はこちら）

2の方式は、Developers Consoleでのトークン発行操作やプロバイダーの管理者権限がなくても使えます。

| 関数 | 内容 |
|---|---|
| `pushMessage(userId, text)` | `POST https://api.line.me/v2/bot/message/push` でテキスト1通を送る。成否を `true`/`false` で返す |
| `pushProvisional(userId, data)` | 仮予約受付の文面で送る |
| `pushConfirmation(userId, reservation)` | 確定の文面で送る |
| `pushCancellation(userId, reservation, wasConfirmed)` | 却下・キャンセルの文面で送る |

送信に失敗する主な原因: お客様が公式アカウントをブロックしている・友だちでない、userIdが別プロバイダーのもの（400 `Failed to send messages`）、チャネルID/シークレットの誤り（トークン取得で失敗）、月の無料メッセージ数の上限。

### 14.4 メール（MailApp）

- `sendEmail_(to, subject, body)` は宛先が空なら何もしない。失敗してもエラーを投げず、Discordに「⚠️ メール送信に失敗しました（件名: …）」
- 差出人はスクリプト所有者のアカウント、表示名は「oO SPACE」
- GASのMailAppには1日あたりの送信上限があります（無料のGmailアカウントで100通程度、Workspaceで1,500通程度）。送信前に `checkEmailQuota_()` で残数を確認し、20件を切ったらDiscordに1日1回だけ警告します

# 第4部 安全に運用・改修するために

## 17. セキュリティ設計

### 17.1 `google.script.run` から呼べる関数（最重要）

Webアプリは「自分として実行」「全員（匿名含む）」で公開しているため、承認画面・管理者画面・ログイン画面を開いた人なら**誰でも**、ブラウザの開発者ツールから `google.script.run.<関数名>()` で、**名前の末尾が `_` でないすべてのトップレベル関数**を、スクリプト所有者の権限で実行できます。ログイン画面は誰でも開けるので、「誰でも呼べる」と考えてください。

トップレベル関数を追加するときは、必ず次のどれに当たるかを決めてください。

| 種類 | やること | 例 |
|---|---|---|
| 内部ヘルパー | 名前の末尾を `_` にする（google.script.runから呼べなくなる。代わりにエディタの関数一覧にも出なくなる） | `getSheet_`、`sendEmail_` |
| 画面から呼ぶ公開API | 誰に呼ばれても安全に作る。操作系は先頭で `isAuthorizedAdmin_(sessionToken)` を確認 | `cancelReservation`、`addUser` |
| GASエディタから手動実行する保守・診断用 | 先頭で `assertEditorRun_('関数名')` | `checkConfig`、`createDailyTrigger`、`debugLine*` |
| トリガーのハンドラー | 先頭で `assertEditorOrTriggerRun_(e, '関数名')`（エディタからの手動実行も可） | `sendReminders`、`archiveOldReservations` |

名前空間オブジェクト（`SheetService` など）の中の関数は、トップレベル関数ではないので `google.script.run` からは呼べません。

**ガードの仕組み**（`Code.js`）:

| 実行のされ方 | `getActiveUser()` | `getEffectiveUser()` | 判定 |
|---|---|---|---|
| GASエディタから実行 | 実行した本人 | 実行した本人 | 一致 → 許可 |
| Webアプリ経由（社内の人） | 訪問者 | スクリプト所有者 | 不一致 → 拒否 |
| Webアプリ経由（匿名・社外） | 空文字 | スクリプト所有者 | 空 → 拒否 |
| 時限トリガー | 不定 | 登録した人 | `triggerUid` の照合で許可 |

- `isEditorRun_()`: 両者が空でなく一致するときだけ `true`。スクリプト所有者本人がWebアプリを開いた場合も一致してしまうが、所有者はもともと全権限を持つので問題ない
- `isOwnTriggerRun_(e, handler)`: イベントオブジェクトの `triggerUid` が、このプロジェクトに登録済みで同じハンドラー名を持つトリガーの `getUniqueId()` と一致すれば `true`
- 拒否時は例外を投げるので、トリガー実行が誤って拒否された場合もGASのトリガー失敗通知メールで気付ける

### 17.2 その他の対策

| 脅威 | 対策 | 場所 |
|---|---|---|
| XSS（お客様の入力が画面でスクリプトとして動く） | 表示は `textContent` か `escapeHtml` を通す | reserve-form.js、AdminPage.html |
| テンプレート埋め込みからの脱出 | `toSafeJson_()`（`<` を `<` に） | 全テンプレート |
| スプレッドシートの数式インジェクション | 書き込み前に `sanitizeCell_()` | SheetService.js |
| 承認時の想定外の列の書き換え | `EDITABLE_FIELDS` の許可リストだけ反映 | Code.js |
| 同時操作による二重登録・二重通知 | スクリプトロック＋ステータスによる二重実行チェック | Code.js |
| ログインリンクによるメールの大量送信 | 同じアドレスへは1分に1回まで | Code.js |
| 登録済みアドレスの推測 | 未登録でも同じ応答 | Code.js |
| 管理者のロックアウト | 管理者が0人になる操作を拒否 | Code.js |
| Discordへの個人情報流出 | 電話番号・メールアドレスを通知に含めない | Code.js、Trigger.js |
| Discordでのメンション悪用 | `allowed_mentions: {parse: []}` | NotifyService.js |
| 秘密情報の漏えい | すべてスクリプトプロパティに置き、ソースコード・リポジトリに書かない | — |
| claspの認証情報の流出 | `.clasprc.json` を `.gitignore` に入れている | .gitignore |

`LIFF_ID`、`GAS_ENDPOINT_URL`、`.clasp.json` の `scriptId` はリポジトリに入っていますが、秘密情報ではありません（どれもブラウザやURLから見える値で、これだけでは操作できない）。Webhook URL、LINEのチャネルシークレット、スプレッドシートIDは**秘密**です。

### 19.1 必要なもの

- GASプロジェクトの編集権限（スクリプト所有者は会社アカウント。[齋藤稜太メモ](saito-ryota-memo.md)）

### 19.2 ブランチ運用

- `main`: 本番。GitHub Pagesと直結しているので、**mainへのマージ＝フロントの本番反映**。直接pushしない
- `develop` / `feature/xxx`（`claude/xxx` を含む）: 開発用。PR経由でmainにマージする
- GASのコードはmainにマージしただけでは反映されない（19.4）。**フロントとGASの反映タイミングがずれる**ので、両方にまたがる変更は「GASを先にデプロイ → フロントをマージ」の順にする（新しいフロントが古いGASに送ってエラーになるのを防ぐ）

### 19.3 フロントエンドの反映

`frontend/` を変更してmainにマージするだけです（GitHub Pagesが自動で公開、数分かかる）。ビルドはありません。ブラウザやLINEアプリのキャッシュで古いJSが残ることがあるので、確認時は再読み込みしてください。

### 19.4 GASの反映（clasp）

初回のみ:

```bash
npm install -g @google/clasp
```

```bash
clasp login
```

コードの反映（`.clasp.json` の `scriptId` のプロジェクトへ `gas/` の中身を上書き）:

```bash
clasp push
```

**`clasp push` だけでは本番（`/exec` のURL）に反映されません。** `push` で変わるのは最新のコード（`/dev` のURLで確認できる）だけで、本番は「デプロイ」したバージョンで動きます。本番に出すには、既存のデプロイを新しいバージョンで更新します。

```bash
clasp deployments
```

```bash
clasp deploy --deploymentId <既存のデプロイID> --description "変更内容"
```

GASエディタの「デプロイ > デプロイを管理 > 編集（鉛筆）> バージョン: 新バージョン > デプロイ」でも同じことができます。

> **新しいデプロイを作らないこと**: 新規デプロイにするとURLが変わり、`config.js` の `GAS_ENDPOINT_URL`・スクリプトプロパティの `WEB_APP_URL`・Discordに出した過去の承認リンク・送信済みのログインリンクがすべて使えなくなります。必ず既存のデプロイIDを指定してください。

GASエディタで直接コードを編集した場合、次の `clasp push` で上書きされて消えます。エディタで直したらリポジトリにも同じ変更を入れてください。

### 19.5 デプロイ後の確認

`docs/test-checklist.md` を上から順に実施します（仮予約 → 承認 → 管理画面 → リマインド → セキュリティ、の順に依存関係がつながっています）。GASを変えたら、少なくとも「予約を1件入れて承認し、管理画面でキャンセルする」までは確認してください。

### 19.6 テストについて

自動テストはありません。GASの処理はGoogleのサービスに依存しているため、動作確認は実機で行います。

- テスト用の予約は、氏名を「テスト」などにして、確認後に管理者画面からキャンセルしておく（空き状況やリマインドに影響しないように）
- お客様に通知が飛ばないよう、メールアドレスは自分のもの、LINEは自分のアカウントで試す
- 本番と別にテスト環境が欲しい場合は、GASプロジェクト・スプレッドシート・カレンダー・Webhookをもう1セット用意し、`.clasp.json` の `scriptId` を切り替える（テスト用LIFFも必要）

### 19.7 ログの見方

- GASエディタ左メニューの「実行数」: 実行ごとの成否と `console.log` / `console.error` の出力
- コード中のログは「関数名: 何が起きたか（予約ID）」の形で書いてあるので、予約IDで探せる
- 外部API呼び出しは必ず `try/catch` し、失敗時は `console.error` に残す（コーディング規約）

## 21. 改修の手引き（よくある変更の手順）

### 21.1 予約の項目を追加する

例: 「利用目的」を追加する場合。

1. `SheetService.js` の `HEADERS` の**末尾**に `'利用目的'` を追加（途中に入れるとデータがずれる）
2. `SheetService.addProvisionalReservation()` の `appendRow` の配列の**末尾**に `sanitizeCell_(data.purpose || '')` を追加（`HEADERS` と同じ順番）
3. `reserve.html` に入力欄を追加し、`reserve-form.js` の `buildSummary()`（確認画面）と送信するJSONに `purpose` を追加
4. 必要に応じて `doPost` に検証を追加
5. 承認画面で編集させるなら、`ApprovalPage.html` に `name="利用目的"` の入力欄を追加し、`Code.js` の `EDITABLE_FIELDS` と `approveReservation` の `updateReservation` に追加
6. 管理者画面の詳細パネル（`AdminPage.html`）と「予約を追加」、`createReservationByAdmin` に追加
7. 通知文に載せるなら `buildProvisionalMessage_` などに追加（個人情報はDiscordに載せない）
8. GASをデプロイしてからフロントをマージ（19.2）

### 21.2 人数の上限・1日の定員を変える

- 1件の上限: `MAX_HEADCOUNT`（Code.js と calendar.js）と、AdminPage.html の人数入力2か所（「予約を追加」と「変更」）
- 1日の定員: `DAILY_CAPACITY`（SheetService.js）と、AdminPage.html の統計タイル

### 21.3 営業時間・時間の選択肢を変える

`calendar.js` の `for (let minutes = 15 * 60; minutes <= 21 * 60; minutes += 30)` を変えます。サーバー側では時刻を検証していないので、GASの変更は不要です。カレンダーの予定の長さ（1時間）を変えるなら `CalendarService.createEvent` の `60 * 60 * 1000`。

### 21.4 定休日・臨時休業を変える

- 曜日を変える: `getClosedReason_()`（Code.js）の `getUTCDay() === 0` と、`calendar.js` の `cellDate.getDay() === 0`（サーバー判定がない日付の保険）、ダミーデータ、`reserve.html` の凡例「休 定休日（日曜・祝日）」、`doPost` のエラーメッセージ
- 臨時休業（年末年始など）を入れたい場合は現在仕組みがありません。たとえばスクリプトプロパティに休業日の一覧を置き、`getClosedReason_()` で照合する、などの追加が必要です

### 21.5 予約できる期間を変える

`BOOKING_MONTHS_AHEAD`（Code.js）を変えるだけで、空き状況JSONの範囲・カレンダーの表示月・`doPost` の受付範囲がそろって変わります。ダミーデータの「3か月」も合わせてください。

### 21.6 スペースを追加する

1. `reserve.html` に `.space-card`（`data-space="〇〇・スペース"`）を追加
2. `AdminPage.html` の「予約を追加」のスペース選択肢に追加
3. `index.html` の紹介を更新
4. 管理者画面の一覧は「・スペース」を除いて表示しているので、名前は「〇〇・スペース」の形にそろえる

### 21.7 通知の文面を変える

[付録B](#付録b-通知文面一覧)の「関数」列の関数を直します。LINEとメールで文面が別関数になっている点、Discordに電話番号・メールアドレスを載せない点に注意してください。

### 21.8 画面から呼ぶサーバー関数を追加する

1. `Code.js` にトップレベル関数を追加
2. 操作系なら、最後の引数を `sessionToken` にして先頭で `if (!isAuthorizedAdmin_(sessionToken)) throw new Error('アクセス権がありません');`
3. 予約データを変えるなら `withReservationLock_()` の中で読み書きする
4. 全体を `try/catch` で囲み、`{success: false, error: String(err.message || err)}` を返す
5. `Date` を返すなら `JSON.parse(JSON.stringify(...))`
6. 画面側は `google.script.run.withSuccessHandler(...).withFailureHandler(...).関数名(..., sessionToken)`
7. 画面に出す値は必ずエスケープ

### 21.9 GASエディタ専用の関数を追加する

先頭で `assertEditorRun_('関数名')` を呼びます。トリガーから呼ぶなら `function 関数名(e) { assertEditorOrTriggerRun_(e, '関数名'); ... }` とし、登録用の関数も用意します。

### 21.10 Discord以外の通知先に変える

`NotifyService` が送信先の違いを吸収しているので、呼び出し側は `NotifyService.send(message)` のままで済みます。Slackなら `SLACK_WEBHOOK_URL` を設定して `DISCORD_WEBHOOK_URL` を消すだけ。別のサービスなら `buildPayload_()` と `isDiscordUrl_()` の判定に分岐を追加します。

## 22. 既知の制約・注意点

コードを読んで分かる、仕様上の割り切りや注意点です。変更するかどうかは運用と相談して決めてください。

1. **承認には権限チェックがない**: `approveReservation` は承認リンク（予約IDはUUIDで推測困難）を知っていれば誰でも実行できる仕様です。Discordのチャンネルに入れる人＝承認できる人、という前提です。予約IDがURLに入るので、承認リンクをお客様など外部に共有しないでください。
2. **（2026-11-10 修正済み）キャンセル済みの予約は承認できない**: `approveReservation` はキャンセル済みの予約をエラーにし、承認画面も仮予約以外ではフォームを出さずに「確定済み」「キャンセル（却下）済み」と表示します。改めて受け付ける場合は管理画面の「予約を追加」から登録します。
3. **承認時は人数・日時などを検証しない**: 承認画面の入力欄は自由入力で、`approveReservation` は人数の範囲や日時の形式を確認しません（メールアドレスだけ検証）。日時を読めない形に書き換えるとカレンダー登録が失敗します。
4. **空き状況は目安で、サーバー側では定員を強制しない**: `doPost` は1日の合計人数を確認しません。仮予約も人数に数えないので、同じ日に申し込みが集中することがあります（スタッフが承認時に判断する運用）。
5. **空き状況の取得に失敗するとダミーデータを表示する**: 本番でもGASへのfetchが失敗するとダミーの空き状況が出ます。その日が実際に予約できるかはサーバー側の検証（期間・定休日）に頼っています。
6. **過去の日付・営業時間外もサーバーでは拒否しない**: `doPost` は過去日や時刻の範囲（15:00〜21:00）を検証しません（フォームでは選べない）。`space`・`drink` などの値も検証せずに保存します。
7. **カレンダーの予定は1時間固定**: 利用時間の入力はなく、開始時刻から1時間の予定を作ります。
8. **人数変更以外の編集は管理画面にない**: 確定後に日時やスペースを変えるには、キャンセルして登録し直すか、スプレッドシートとカレンダーを手で直す必要があります（手で直した場合、カレンダーとシートの整合はとれません）。
9. **人数変更・管理画面からの追加ではお客様に連絡しない**: お客様からの依頼で変更する想定のためです。
10. **お客様自身はキャンセルできない**: LINEのトークで連絡してもらい、スタッフが管理者画面でキャンセルします。
11. **リマインドは途中で止まると残りが送られない**: `sendReminders` は1件の処理で例外が出ると、それ以降の予約に送りません（各送信は個別に失敗を握りつぶすので、通常は起きにくい）。
12. **アーカイブ後のデータは画面に出ない**: 180日より前の予約は「予約一覧_archive」シートを直接見る必要があります。
13. **スプレッドシートの全行読み込み**: 1件の検索でもシート全体を読み込んでいます。行数が増えるほど遅くなるため、アーカイブで行数を抑えています。
14. **ヘッダー行の自動上書き**: [5.1](#51-シート予約一覧) のとおり、`HEADERS` の途中に列を足すとデータがずれます。
15. **管理者画面の並び順**: 予約日時を文字列として並べています。シートの値が文字列（`2026-11-20T18:00:00`）とDate（JSONで `2026-11-20T09:00:00.000Z`）で混ざると、並びが前後することがあります。
16. **旧LIFF由来のuserId**: 旧LIFF（`2011761592-fPsPphNA`、別プロバイダー）で取得したuserIdが残っている予約には、LINE通知が届きません。
17. **ドキュメントのずれ**: `docs/spec.md` は未記入です。`docs/test-checklist.md` の「0. 前提確認」は `LINE_CHANNEL_ACCESS_TOKEN` を挙げていますが、現在の本番は `LINE_CHANNEL_ID` + `LINE_CHANNEL_SECRET` を使っています。README.mdの事前準備チェックリストも初期のままです。

## 付録D. 用語集

| 用語 | 意味 |
|---|---|
| LIFF | LINE Front-end Framework。LINEアプリ内でWebページを開き、LINEのユーザー情報を取れる仕組み |
| LIFF ID | LIFFアプリの識別子。LINE Loginチャネルの中に作る |
| userId | LINEのユーザーID（`U`で始まる）。**プロバイダーごとに別の値**になる |
| プロバイダー | LINE Developersでチャネルをまとめる単位（会社・組織） |
| Messaging APIチャネル | 公式アカウントからメッセージを送るためのチャネル。`@186lmmed` のもの |
| LINE Loginチャネル | LIFFアプリを置くチャネル。Messaging APIチャネルと同じプロバイダーに作る |
| ステートレストークン | LINEのアクセストークンの一種。チャネルID/シークレットからその都度発行し、15分有効 |
| GAS | Google Apps Script。Googleのサービスを操作できるJavaScript実行環境 |
| clasp | GASのコードをローカルとやり取りするコマンドラインツール |
| デプロイ | GASのコードの特定バージョンをWebアプリとして公開すること。`/exec` のURLが固定で付く |
| スクリプトプロパティ | GASプロジェクトに保存するキーと値。秘密情報の置き場所 |
| `google.script.run` | GASのHTML画面からサーバー側の関数を呼ぶ仕組み |
| Webhook | URLにPOSTするだけでメッセージを投稿できる仕組み（Discord/Slack） |
| 仮予約 | お客様が申し込んだだけで、スタッフが未確認の予約 |
| 確定 | スタッフが承認した予約。カレンダーに登録され、空き状況の人数に数えられる |
| 承認リンク | `?page=approval&id=<予約ID>`。Discordの新規予約通知に載る |
| ログインリンク | `?page=admin&session=<トークン>`。社外アカウントの管理者画面用 |
| アーカイブ | 古い予約を別シートへ移すこと |
